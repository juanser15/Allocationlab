---
name: Allocation Lab v2 navigation structure
description: The current sidebar order and how sub-workflows/settings are merged into it
---

Allocation Lab v2's left nav is exactly 4 items, in this order: Dashboard, Portfolio Lab, Research Lab, Investment Committee. Settings is NOT a sidebar item and NOT a routed page — it is a global right-side Sheet ("Configuration Console") opened from the top-right gear via `useSettingsDrawer().openSettings(sectionId?)`, with its own internal left-nav of 9 sections (Data Sources, Universe, Portfolio Constraints, Previous Weights, Execution Assumptions, Model & Factors, Benchmarks, Reporting Defaults, Governance & Advanced) and Save/Cancel/Reset Section/Restore Institutional Defaults + unsaved-changes-on-close guard.

**Why:** Nav structure has changed repeatedly (9 sections → 7 → 5-module+gear-linking-to-/settings-page → this 4-module+gear-drawer layout). Settings itself moved from a routed `/settings` page with tabs to a non-routed global drawer (Sheet) so it can be triggered contextually from any page. `/settings` and `/configuration` routes now just redirect to `/`. Treat nav/settings structure as a snapshot that can change again — always check current `Sidebar.tsx` / `SettingsDrawer.tsx` rather than trusting a remembered layout.

**How to apply:** When adding a new feature/workflow, do not create a new top-level route/sidebar entry or a new settings route. For app modules, add a tab within the closest existing page. For global config, add a section inside `SettingsDrawer.tsx`'s `SECTIONS` array + `context/settings-drawer-context.tsx`'s `SettingsSectionId` union, not a new page. Any in-page CTA that used to link to `/settings` (e.g. "no price data" banners, constraint-compliance descriptions) must instead call `openSettings("<section-id>")` via the context hook — grep for stray `href="/settings"` after any change, since wouter `Link` to a redirect-only route silently loses the intended section. Settings state not yet backed by a DB table (execution assumptions, benchmarks, reporting defaults, governance) is persisted to `localStorage` via `lib/local-settings.ts`, not faked — this is a deliberate scope decision, not a placeholder.

Research Lab's tab order is fixed to a config→test→results→diagnostics sequence, not an arbitrary list: 1) Overview (regime/market health status), 2) ETF & Factor Explorer, 3) Backtesting (config + run), 4) Bias Audit / Integrity Checks, 5) Walk-Forward & Sensitivity, 6) Scenario & Stress Lab (two labeled sub-sections: Scenario Analysis for user-defined shocks [SPX/rates/USD/oil/vol/credit], Stress Testing for historical pre-defined episodes [COVID/2022 rates shock/regional banking crisis/tech unwind/custom windows]), 7) Research Notes. Diagnostics tabs (Bias Audit, Walk-Forward, Sensitivity) must never render analysis before their generating backtest has actually run — gate on `bt.hasSufficientData`.

Dashboard must never contain clickable cross-module CTAs (no "Go to X" links/buttons jumping to other modules, including in empty-state alerts or "next step" cards) — it is a read-only status overview only. Individual ETF ticker links (`/etf/:ticker`) are the sole exception, since they're inline data drill-downs, not module navigation.

`/reports` and `/archive` are wouter redirects into `/investment-committee` — the actual `Reports`/`Archive` components render inside Investment Committee's own `Tabs` ("Report"/"Archive" triggers), not as standalone routed pages. Screenshotting `/reports` correctly shows the Investment Committee page (defaulting to its "Decision Room" tab); that's expected, not a bug.
