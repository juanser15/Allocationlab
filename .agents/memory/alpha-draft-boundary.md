---
name: Alpha draft bulk-generation boundary
description: Preserve draft-only creation, server-owned frozen identities, and existing definitions when simplifying alpha creation.
---

Bulk alpha creation appends unique executable definitions; it must not replace manually configured definitions or execute B1 preparation or downstream models.

**Why:** Simplifying creation should not discard prior work or convert a draft edit into a financial calculation. Display aliases are not new strategies.

**How to apply:** Preview new, skipped-duplicate, and resulting draft counts using the same definition generator as the explicit creation action. Keep preparation/freeze and Optimize separate. Parameter edits affect the proposed additions, not existing definitions.

Never present a draft identity as a final canonical candidate ID. Keep stable ordering for newly generated peer universes, but do not reorder older draft or frozen universes.

**Why:** Final identities depend on the frozen dataset and factor version, and B1 canonicalization preserves array ordering. A seemingly harmless cleanup of old peer order can change an existing identity.

**How to apply:** Show factor, assets, mapping, and parameters in the draft preview; let the unchanged B1 engine assign final IDs. Test aliases, duplicate prevention, and cutoff isolation against B1 rather than introducing another financial identity algorithm.
