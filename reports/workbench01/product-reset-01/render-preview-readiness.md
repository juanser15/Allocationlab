# Preview readiness — owner deployment only

No deployment, main/render-preview update, merge or PR is performed in this phase.

Use the existing Node workspace build/start arrangement. Backend build: `node artifacts/api-server/build.mjs`; frontend build: `PORT=5173 BASE_PATH=/ artifacts/allocation-lab/node_modules/.bin/vite build --config artifacts/allocation-lab/vite.config.ts`. Start the actual built backend with `node --enable-source-maps artifacts/api-server/dist/index.mjs`. The new `workbench-interactive-worker.mjs` must be present alongside the existing worker artifacts. Serve the existing frontend `artifacts/allocation-lab/dist/public` with SPA fallback and same-origin `/api` forwarding. Open `/workbench`. Legacy root behavior remains separate.

Required runtime variables: platform PORT; server-only WORKBENCH_PREVIEW_TOKEN (strong owner-provided secret); isolated WORKBENCH_RUN_DIR (dedicated /tmp path outside the repository); and DATABASE_URL as required by the existing application bootstrap. Workbench does not use a database. For an isolated Workbench-only preview set the existing VALIDATION_JOB_WORKER_DISABLED=1 flag to stop the unrelated legacy supervisor; DATABASE_URL is still required by application bootstrap. No token may be supplied to Vite or embedded in assets. The owner enters it manually; it stays in tab sessionStorage and Bearer headers. The API fails closed without it.

Keep committed certified source, configs, identity source files and the CSV in the runtime tree. Git metadata is not required. Existing certified-marker root discovery and storage-overlap/symlink protection remain unchanged. A container that ships only dist without these identified source/data files cannot reproduce or initialize this contract.

Optional operational variables retain their existing defaults: WORKBENCH_MAX_JOBS=2000; WORKBENCH_MAX_ENGINE_FILES=512; WORKBENCH_EXECUTION_TIMEOUT_MS=120000; WORKBENCH_MAX_OUTPUT_BYTES=67108864. Invalid settings fail startup. No default was increased. One persistent bounded child executes at a time; it reuses prepared data within that process. Allow memory headroom for the API plus its child (child heap cap 768 MiB; caches are separately bounded). Temporary files and caches are not durable and do not survive all restarts. Crash-abandoned leases require owner inspection, not automatic lease removal.

No queue, external object store or production authentication system is claimed. Suggested next phase: explicit background/extended jobs with authenticated handles, durable admission and immutable external artifacts; see interactive-execution-architecture.md. Coming modules and Certify remain non-executable. Browser testing uses real Chromium responsive viewports; this is not physical Android or production certification.
