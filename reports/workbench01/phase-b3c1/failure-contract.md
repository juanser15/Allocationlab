# Actionable failure contract

Ordinary V2 plan/submission/rerun blockers use the existing safe error envelope. `error.code` and `error.issues.error_class` identify the verified cause. Issues include `failed_stage`, `failed_fold_id` and `failed_decision_date` where applicable, `safe_message`, `actionable_explanation`, `suggested_user_action` and `diagnostic_reference`. A pre-run blocker uses `PRE_RUN_NO_ATTEMPT_CREATED`; it does not manufacture a failed execution. Necessary preflight checks are described in successful plans with `candidate_viability_guaranteed: false` and `financial_backtests_executed: 0`.

For failed attempts, ordinary preview-authenticated GET run details add the same fields to the latest result, latest attempt and each failed history entry. Existing status remains FAILED. Earlier successful results remain separate. The safe diagnosis uses actual engine summary, training-job metrics and the unchanged candidate-selection function. Classes distinguish NO_VALID_CANDIDATE, INSUFFICIENT_SELECTION_HISTORY, DATA_AVAILABILITY_FAILURE, WORKER_PROTOCOL_FAILURE, WORKER_EXECUTION_TIMEOUT and OUTPUT_OR_LOG_LIMIT. An evidence gap returns UNCLASSIFIED_CANDIDATE_FAILURE, UNCLASSIFIED_EXECUTION_FAILURE or DIAGNOSTIC_EVIDENCE_UNAVAILABLE. A committed engine defect is not claimed from an unexplained job failure, and no financial remedy is invented.

NO_VALID_CANDIDATE includes the failed fold, decision date, usable observation count and candidate constraint breaches. It distinguishes a VALID training job from a policy rejected by selection constraints. Defined scores are retained as training evidence, not presented as OOS performance. An insufficient-metric diagnostic does not assume that a longer calendar window will fix zero variance.

Full bounded worker diagnostics stay in the existing private `diagnostic.json`. The derived, redacted record is published exclusively as `failure-diagnostic-v1.json` under the same attempt, with its own canonical payload hash and evidence hashes. Original `attempt.json`, states, `safe-error.json`, `diagnostic.json`, `result.json`, engine outputs and sealed evidence are not rewritten or deleted. Repeated reads reuse the immutable sidecar. Invalid paths, symlinks, nonregular files and oversized evidence fail closed. Original failure references remain available for owner inspection outside the public API.

No new arbitrary-file or raw-diagnostic endpoint is added. Existing preview authentication protects the run-details response; missing/wrong token returns 401. Stack traces, absolute paths, environment values, secrets and raw worker stderr are not returned. The UI validates the additive fields, renders the actual class/fold/reason/action and rejects private-looking text. Unknown diagnostic keys are not rendered.

The exact rejected design, direct POST bypass attempt and rerun of its retained historical failure all block before creating another execution. The blocked response never repairs dates, training, costs, policies, constraints or fold count. Successful specifications retain their prior normalization, identity and financial hashing. Backend execution and benchmark implementations are byte-preserved.
