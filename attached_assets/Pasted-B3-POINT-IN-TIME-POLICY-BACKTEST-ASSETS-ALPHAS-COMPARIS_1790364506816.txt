B3 — POINT-IN-TIME POLICY BACKTEST & ASSETS/ALPHAS COMPARISON

CLOSED-SCOPE TASK

Stage A, B1 and B2 are closed.
Reuse their engines, snapshots and tests.

GOAL

Historically evaluate the B2 allocation policy for:
1. Asset returns.
2. Tradable alpha streams.

Recompute allocations through time and execute the resulting underlying
asset portfolio through A1.

Produce comparable, persisted results for both representations.

Do NOT implement:
- new objectives or covariance estimators;
- predictive fitting of raw signals;
- automatic candidate selection;
- parameter optimization;
- PCA, clustering or ensembles;
- new execution models or navigation redesign.

--------------------------------------------------
1. FREEZE THE POLICY, NOT TODAY'S WEIGHTS
--------------------------------------------------

Each validation must reference a frozen B2 policy definition containing:

- representation and canonical candidates;
- B1 signal definitions, mappings and peer universes;
- objective;
- expected-return shrinkage s;
- covariance shrinkage delta;
- gamma and eta where applicable;
- estimation lookback and minimum observations;
- supported constraints;
- engine/solver versions.

Freeze validation assumptions separately:
- evaluation start/end;
- decision calendar and execution convention;
- initial NAV and holdings/cash;
- transaction costs and slippage;
- cash-yield assumption;
- benchmark, when selected.

Use an explicitly identified immutable dataset covering warmup and
evaluation. If the original dataset lacks coverage, require explicit
selection of another frozen validation dataset.

Never substitute the latest working dataset automatically.

Today’s b, H, mu and Sigma are NOT historical inputs.
Recompute them at each historical decision using then-available data.

--------------------------------------------------
2. ONE DECLARED DECISION CALENDAR
--------------------------------------------------

For B3, require a common declared decision calendar and compatible
execution convention for the allocator and selected alpha streams.

Reject incompatible schedules explicitly.
Do not silently change a candidate's saved definition.

Use A1 same_close or next_close conventions.
Keep next_open unsupported without opening-price data.

At every scheduled decision:

1. Determine the A1 information cutoff.
2. Update B1 signals and stream state using only available observations.
3. Select completed historical return intervals within the estimation
   window; none may end after the information cutoff.
4. Recompute B2 mu and Sigma.
5. Build the contemporaneous B1 target-exposure mapping H and cash d.
6. Solve B2 with the frozen objective and constraints.
7. Save the decision, inputs, solver status and targets.
8. Execute at the declared later event through A1.

Preserve B1 state from its declared initialization through warmup.
A rolling estimation window must not reset stream holdings or NAV.

Do not reuse end-of-sample coverage, rankings or correlations to
filter earlier candidates.

Freeze the selected candidate set. Insufficient history at the requested
start must be reported; do not silently alter the start or candidate set.

This is rolling fixed-specification evaluation:
estimates update through time, but the policy and hyperparameters do not
get selected using subsequent performance.

Do not label it independent model-selection validation or bias-free.

--------------------------------------------------
3. EXECUTE ONE UNDERLYING ASSET BOOK
--------------------------------------------------

At each decision:

Asset mode:
    H = identity
    d = zero

Alpha-stream mode:
    H = contemporaneous B1 target-exposure matrix
    d = contemporaneous internal cash fractions

Then:

    target_assets = H * b
    target_total_cash = c + d' * b

Include the most recent alpha target updates at that decision.
Do not freeze today's H or historical terminal weights.

Targets are not executed holdings.

Use A1 to carry existing quantities through the execution close,
execute trades, and track subsequent holdings drift.

Between scheduled executions:
- maintain quantities;
- accrue declared cash return;
- do not rebalance implicitly to target weights.

Do not calculate master-book performance as a weighted average of
standalone alpha net-return series.

B1 gross histories feed estimation.
Actual master-book P&L comes from the underlying holdings ledger.

Do not reset the master portfolio to reference capital at each rebalance.

--------------------------------------------------
4. COSTS, CASH AND CONSTRAINTS
--------------------------------------------------

Aggregate desired trades by underlying asset before charging costs.

Opposing alpha instructions in the same asset at the same execution
event offset before external traded notional is calculated.

Apply existing A1 costs/slippage once to external trades.
Do not additionally subtract standalone alpha costs.

Count internal alpha cash and unallocated master cash once.
Accrue yield on actual consolidated cash.

Preserve A1 self-financing treatment:
- no invented external cash;
- no undeclared borrowing to pay costs;
- requested versus executed targets and any cost-related difference
  must be explicit.

Do not change B2's gross-return objective into a cost-aware objective.
Execution costs affect simulated net results, not the frozen solver.

Check B2 constraints on each decision target.
Separately record executed exposures and market drift.

Do not claim target constraints guarantee continuous compliance between
rebalances; do not add hidden trades to enforce that claim.

If data, supported constraints or solver status prevent a valid decision,
stop with the date and reason.
No substitute equal-weight or cash portfolio unless that is the actual
valid B2 solution.

A partial diagnostic ledger must not appear as a successful full-period
backtest.

--------------------------------------------------
5. RESULTS AND COMPARABILITY
--------------------------------------------------

Persist:
- daily NAV and net returns;
- actual asset holdings and cash;
- daily asset/cash P&L, fees and slippage;
- external traded notional;
- each decision's cutoff, estimation window and input identity;
- mu, Sigma, H, d, b and target asset exposures;
- solver and constraint checks;
- reconciliation results.

Display:
- net equity curve and drawdown;
- cumulative return and annualized return;
- annualized volatility;
- Sharpe based on DAILY excess returns;
- maximum drawdown;
- monthly returns;
- traded notional/turnover with an explicit convention;
- cash and asset-exposure history;
- alpha-capital weights at decision dates.

Compute:

    excess_t = net_return_t - declared_daily_cash_yield_t

    Sharpe = sqrt(252) * mean(excess) / sample_std(excess)

Use decimal daily returns and disclose annualization.
If volatility is zero or observations are insufficient, show undefined
with a reason, not fabricated zero or infinity.

Label partial calendar months.
Show costs in reconciled monetary units; do not equate a simple sum of
cost percentages with compounded performance drag.

Allow side-by-side comparison of saved asset-mode and alpha-mode runs.

A matched comparison requires:
- identical evaluation dates and underlying market data;
- same initial NAV/holdings;
- same calendar, execution and cash assumptions;
- same cost model;
- same final-asset constraints and capital budget;
- visible estimation/objective settings for each run.

Flag configuration differences rather than presenting an unmatched
comparison as controlled.

Different realized turnover and risk are legitimate outcomes.
Do not rescale either result retrospectively to make it look better.

Do not automatically declare a winner or tune parameters after comparison.

Disclose fixed-candidate-universe and adjusted-price-data limitations.

--------------------------------------------------
6. PERSISTENCE AND UI
--------------------------------------------------

Use the existing immutable Validation Run mechanism.

Persist policy identity, dataset hashes, assumptions, decision records,
ledger, results and engine/solver versions.

A rerun with different assumptions creates another Validation Run.
Historical results remain unchanged and retrievable after reload.

Connect the existing Validate action to B3 for supported B2 policies.
Do not dispatch those requests to the legacy allocation constructor.

Keep existing Portfolio Lab/Backtest surfaces.

Show:
- selected policy and representation;
- Configure -> Validate -> Results -> Diagnostics;
- validation ID, dates and status;
- saved-run comparison.

No new top-level tab, command center or report redesign.

Successful status means:
“Historical simulation completed; accounting checks passed.”

It does not mean alpha efficacy or out-of-sample profitability is proven.

--------------------------------------------------
ACCEPTANCE TESTS
--------------------------------------------------

T1 — Historical decisions reproduce isolated B2 solves

At three or more historical decision dates, independently call B2 using
the exact truncated inputs.

Compare estimates, mappings, candidate weights and targets with the
corresponding B3 decisions within 1e-8.

Exercise both B2 objectives.

T2 — Future-data isolation

Alter prices strictly after cutoff T.
Also introduce a missing observation after T.

Decisions, trades and P&L through T must remain unchanged.
No full-period preprocessing or future coverage filter may alter them.

T3 — Execution and holdings

Exercise same_close and next_close.

A newly purchased asset must not earn the pre-purchase jump.
Quantities remain unchanged between executions while weights drift.
Every daily ledger reconciles within the A1 tolerance.

T4 — Equivalent representations

Use direct assets and economically equivalent always-invested alpha
streams under identical policy and execution assumptions.

Require a nonzero risky allocation and actual trades.

Underlying targets, executions, cash and net NAV must agree within 1e-8.

T5 — Netting, cash and costs

Use deterministic alpha instructions with opposing trades in the same
asset at the same execution event.

Verify external cost is charged on the aggregate net trade, not both
internal instructions.

Include a zero-net-trade case and a nonzero-net-trade case.
Independently reconcile internal plus master cash and cost accounting.

T6 — Explicit failures

Verify:
- missing held-asset prices;
- a historically infeasible constraint set;
- incompatible alpha/allocator schedules;
- failed solver status.

Each must return an explicit dated failure, without fabricated returns,
silent candidate removal or a successful substitute portfolio.

T7 — Five assets versus thirty streams

Run both representations over multiple decision dates using the B1
five-asset/thirty-stream fixture.

Use predeclared feasible settings requiring positive risky exposure.
Require actual executions at two or more dates.

Verify the full master ledger, per-decision constraints and comparison
metadata. An all-cash run cannot satisfy this acceptance case.

Retain a separate valid all-cash control with correct cash return and
undefined zero-risk metrics.

T8 — Real UI/API persistence and replay

Run B3 through the actual UI/API flow and save the Validation Run.

Change working data/configuration and reload with a fresh client.
Retrieve and replay the saved run.

Financial outputs reproduce within 1e-8; identities remain unchanged.
A second run with different costs must not overwrite the first.

Run A1, A2, A2.1, A3, B1 and B2 regression suites plus typecheck.

Tests must include expected and observed results.
Synthetic fixtures are test data, never market evidence.

--------------------------------------------------
DELIVERABLE AND STOP
--------------------------------------------------

Return only:
- exact decision/execution calendar;
- how B1, B2 and A1 are connected;
- asset-book and cost conventions;
- T1–T8 expected/observed and PASS/FAIL;
- maximum reconciliation and replay differences;
- actual regression/typecheck results;
- blocking limitation, if any.

One implementation pass plus at most one targeted repair pass.

All criteria pass: B3 CLOSED, then STOP.
Any required criterion fails: B3 BLOCKED with the exact failure, then STOP.

Do not begin factor selection, hyperparameter search or additional models.
