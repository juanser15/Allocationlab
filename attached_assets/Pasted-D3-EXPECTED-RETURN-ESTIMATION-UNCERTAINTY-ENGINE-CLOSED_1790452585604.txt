D3 — EXPECTED RETURN ESTIMATION & UNCERTAINTY ENGINE

CLOSED-SCOPE TASK

Stages A, B, C1, C2, C3, D1 and D2 are CLOSED.

GOAL

Create a first-class Expected Return / Forecast layer for:

1. Asset Returns
2. Tradable Alpha Streams
3. Signed Alpha Overlay excess returns

Expected return estimation must become an explicit, versioned,
auditable input to portfolio construction.

D3 addresses one specific institutional problem:

EXPECTED RETURNS ARE HIGHLY ESTIMATION-ERROR SENSITIVE.

D3 must improve the estimation and transparency of mu.

D3 does NOT:

- change covariance/risk methodology;
- implement robust portfolio optimization;
- optimize transaction costs;
- optimize raw signal coefficients;
- select alphas;
- change C1/C2/C3 research policies;
- introduce new portfolio objectives;
- introduce new execution models;
- auto-tune parameters using backtest performance.

Those belong to later stages.

--------------------------------------------------
1. STRICT LAYER SEPARATION
--------------------------------------------------

The investment pipeline must remain conceptually separated:

INPUTS
    ↓
EXPECTED RETURN MODEL
    mu_hat + uncertainty
    ↓
RISK MODEL
    Sigma / Gamma
    ↓
PORTFOLIO OBJECTIVE
    B2 / D2
    ↓
CONSTRAINTS
    ↓
EXECUTION / B3 / A1

The Expected Return Engine outputs forecasts.

It does NOT output portfolio weights.

The Risk Model does NOT estimate expected returns.

The optimizer consumes both.

Do not merge these layers.

--------------------------------------------------
3. EXPECTED RETURN MODELS
--------------------------------------------------

Support exactly three forecast estimators in D3:

A. SAMPLE_MEAN

B. SHRUNK_MEAN

C. BAYESIAN_VIEWS

Do not add more estimators in D3.

The user explicitly selects the forecast model.

Historical snapshots retain their original estimator.

--------------------------------------------------
4. MODEL A — SAMPLE MEAN
--------------------------------------------------

Given aligned return observations:

r_t ∈ R^N
t = 1,...,T

compute:

mu_sample
=
(1/T) * sum_t r_t

Use exactly the same aligned historical window used for expected-return
estimation.

Report:

- T observations;
- start/end date;
- candidate identities;
- sample mean;
- sample standard deviation;
- standard error of the mean.

Using the selected contemporaneous risk covariance Sigma:

MeanUncertainty
=
Sigma / T

Therefore:

SE_i
=
sqrt(Sigma_ii / T)

Do not treat the sample mean as known.

Do not label:

mu_sample / SE

as a guaranteed predictive t-statistic.

It is an estimation diagnostic only.

--------------------------------------------------
5. MODEL B — SHRUNK MEAN
--------------------------------------------------

Implement explicit linear shrinkage:

mu_shrunk
=
(1 - s) * mu_sample
+
s * mu_prior

where:

0 <= s <= 1

s is USER-CONFIGURED and frozen.

Do NOT select s by maximizing historical Sharpe or portfolio return.

DEFAULT PRIOR

The prior must respect the return convention.

For gross-return modes:

default:

mu_prior_i = daily cash yield

for every candidate.

For signed excess-return mode:

default:

mu_prior_i = 0

because candidate returns are already measured relative to cash.

Allow explicit USER_DEFINED prior vectors.

Do not silently change the prior.

Report separately:

- mu_sample;
- mu_prior;
- shrinkage strength s;
- mu_shrunk;
- shrinkage displacement:

ShrinkageDelta_i
=
mu_shrunk_i - mu_sample_i

--------------------------------------------------
6. SHRINKAGE UNCERTAINTY
--------------------------------------------------

For D3's simple SHRUNK_MEAN estimator, treat the configured prior
as deterministic unless explicitly declared otherwise.

Then:

Var(mu_shrunk)
=
(1 - s)^2 * Sigma / T

This is estimator uncertainty conditional on the fixed prior assumption.

Display that assumption explicitly.

Do NOT claim it includes prior uncertainty.

If:

s = 1

and prior is deterministic,

the reported sampling uncertainty is zero by construction.

Display:

“Forecast entirely determined by fixed prior.”

Do not imply statistical certainty about the true expected return.

--------------------------------------------------
7. MODEL C — BAYESIAN VIEWS
--------------------------------------------------

Implement a general Gaussian Bayesian forecast update.

Do not call this Black-Litterman equilibrium unless an actual
equilibrium-return prior is implemented.

Name the estimator:

BAYESIAN_VIEWS

Let prior expected returns be:

mu ~ N(m, V_prior)

User supplies or selects:

- prior mean m;
- prior uncertainty V_prior.

Views are linear:

P mu = q + epsilon

epsilon ~ N(0, Omega_view)

where:

P = view exposure matrix
q = expected view values
Omega_view = view uncertainty covariance

Posterior precision:

V_post^(-1)
=
V_prior^(-1)
+
P' Omega_view^(-1) P

Posterior covariance:

V_post
=
[
V_prior^(-1)
+
P' Omega_view^(-1) P
]^(-1)

Posterior mean:

mu_post
=
V_post
[
V_prior^(-1) m
+
P' Omega_view^(-1) q
]

Use stable linear solves.
Do not explicitly invert matrices when avoidable.

--------------------------------------------------
8. SUPPORTED BAYESIAN VIEW TYPES
--------------------------------------------------

Support two view types:

A. ABSOLUTE VIEW

Example:

mu_A = q

P row:

[1, 0, 0, ...]

B. RELATIVE VIEW

Example:

mu_A - mu_B = q

P row:

[1, -1, 0, ...]

Allow multiple simultaneous views.

Each view requires explicit uncertainty.

Do NOT interpret “90% confidence” through an undocumented heuristic.

The UI should accept:

View Standard Error

or:

View Variance

using clearly stated units.

Internally:

Omega_view

must be explicit and persisted.

--------------------------------------------------
9. PRIOR OPTIONS FOR BAYESIAN VIEWS
--------------------------------------------------

D3 supports these prior-mean sources:

A. SAMPLE_PRIOR

m = mu_sample

B. SHRUNK_PRIOR

m = previously calculated SHRUNK_MEAN

C. USER_DEFINED_PRIOR

explicit vector supplied by user.

Do NOT implement market-cap equilibrium Black-Litterman in D3.

That requires a separate, properly defined equilibrium-prior contract.

Do not label USER_DEFINED_PRIOR as Black-Litterman.

--------------------------------------------------
10. PRIOR UNCERTAINTY
--------------------------------------------------

Support:

V_prior
=
tau * Sigma

where:

tau > 0

and Sigma is the selected contemporaneous B2/D1 risk covariance
for the SAME candidate ordering and estimation cutoff.

tau is user-configured and frozen.

Also allow an explicit positive-semidefinite user-supplied prior
uncertainty matrix when supported by the API.

Default:

tau = 1 / T

Do not auto-tune tau using realized portfolio performance.

Validate:

- dimensions;
- finite values;
- symmetry;
- positive semidefiniteness;
- candidate ordering.

Invalid prior uncertainty returns:

INVALID_FORECAST_MODEL

11. FORECAST UNCERTAINTY AS FIRST-CLASS OUTPUT
--------------------------------------------------

Every forecast estimator must output:

- expected return vector mu_hat;
- forecast uncertainty covariance V_mu;
- per-candidate forecast standard error;
- estimation window;
- observation count;
- estimator identity;
- estimator parameters;
- prior information where applicable.

For every candidate display:

Forecast SE

The ratio is a signal-to-estimation-noise diagnostic.

Do NOT automatically:
- filter candidates;
- set weights to zero;
- call it statistical significance;
- use arbitrary p-value cutoffs.

12. CONFIDENCE INTERVAL DISPLAY
--------------------------------------------------

For descriptive purposes report:

mu_hat_i ± z * SE_i

Default:

z = 1.96

Label:

“Gaussian forecast-uncertainty interval under model assumptions.”

Do not call this a guaranteed realized-return interval.

The PM may configure z for display only.

Changing display z must NOT change portfolio weights.

--------------------------------------------------
14. PORTFOLIO FORECAST UNCERTAINTY
--------------------------------------------------

For a solved portfolio weight vector w:

ExpectedPortfolioReturn
=
w' mu_hat

ForecastVarianceOfExpectedReturn
=
w' V_mu w

ForecastSEPortfolio
=
sqrt(w' V_mu w)

For signed alpha mode use:

a

instead of capital weights w.

This is uncertainty in estimated expected return.

It is NOT portfolio return volatility.

Display separately:

EXPECTED RETURN UNCERTAINTY

versus:

PORTFOLIO RISK

Do not combine them into one number in D3.

from D3.

The selected risk model separately supplies:

Sigma or Gamma.

Portfolio objectives remain unchanged.

For example:

Regularized mean-variance:

minimize

gamma/2 * w' Sigma w
+
eta/2 * w'w
-
mu_hat' w

Signed overlay:

minimize

gamma/2 * a' Sigma a
+
eta/2 * a'a
-
mu_excess_hat' a

Do not change objective semantics.

return estimator.

Do not migrate old snapshots silently.
