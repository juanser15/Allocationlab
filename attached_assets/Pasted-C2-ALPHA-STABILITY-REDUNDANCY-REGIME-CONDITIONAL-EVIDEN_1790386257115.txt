C2 — ALPHA STABILITY, REDUNDANCY & REGIME-CONDITIONAL EVIDENCE

CLOSED-SCOPE TASK

Stages A and B are closed.
C1 is closed.

Reuse:
- B1 alpha-stream definitions and lineage;
- B2 optimized policies;
- B3 point-in-time backtesting;
- C1 full-versus-exclusion comparisons;
- existing immutable snapshots and Validation Runs.

GOAL

Build an institutional evidence layer answering:

1. Is an alpha economically stable through time?
2. Is an alpha redundant with another alpha?
3. Does an alpha add value only in specific market regimes?
4. Can two highly correlated full-sample alphas still provide
   regime-dependent complementarity?
5. Is the incremental contribution observed in C1 stable across time?

C2 must produce evidence.

C2 must NOT automatically:
- delete alphas;
- rank alphas into winners/losers;
- select the highest Sharpe;
- select the best historical subset;
- cluster and replace candidates;
- run PCA;
- change B2 weights;
- optimize hyperparameters;
- promote a candidate to production.

Those decisions belong to a later policy-comparison stage.

--------------------------------------------------
1. ANALYSIS OBJECT
--------------------------------------------------

C2 operates primarily on TRADABLE ALPHA STREAMS.

Every analyzed stream must reference:
- canonical B1 alpha ID;
- parent signal/factor definition;
- position mapping;
- frozen dataset identity;
- B2/B3 policy identity where applicable;
- historical gross and net returns;
- actual underlying exposures;
- costs and turnover;
- available point-in-time regime labels.

Do not confuse:
- signal values;
- alpha-stream returns;
- underlying asset returns;
- alpha capital weights;
- final asset exposures.

Each diagnostic must state exactly which quantity it uses.

--------------------------------------------------
2. NO SINGLE “REDUNDANCY” METRIC
--------------------------------------------------

For every selected alpha pair calculate separately:

A. FULL-SAMPLE ALPHA-RETURN CORRELATION

Pearson correlation on aligned alpha-stream returns.

Show:
- correlation;
- start/end date;
- paired observation count.

B. ROLLING ALPHA-RETURN CORRELATION

User-configurable rolling window.

Default:
63 trading observations.

Show the complete time series, not only an average.

C. REGIME-CONDITIONAL ALPHA-RETURN CORRELATION

For each sufficiently populated regime:

corr(alpha_i returns, alpha_j returns | regime = r)

Show:
- regime;
- correlation;
- paired observations;
- mean returns of each alpha;
- volatility of each alpha.

D. UNDERLYING EXPOSURE SIMILARITY

At matched decision dates compare the normalized underlying-asset
exposure vectors generated by the two alphas.

Use:

ExposureDistance_t
=
0.5 * sum_assets |h_i,t - h_j,t|

Also report an exposure-similarity representation:

ExposureSimilarity_t
=
1 - ExposureDistance_t

when the exposure vectors use the same declared normalization.

Do not compute fake similarity for two undefined/zero vectors.

E. CAPITAL-ALLOCATION BEHAVIOR

When both alphas belong to the same B2/B3 policy, show their historical
optimized capital weights.

Do not treat similar optimized weights as evidence of similar signals.

--------------------------------------------------
3. REGIME ANALYSIS IS FIRST-CLASS
--------------------------------------------------

Do NOT infer redundancy from full-sample correlation alone.

A pair may be highly correlated in the full sample while behaving
differently conditionally.

Example pattern that must remain visible:

Full-sample correlation:
0.92

Risk-On correlation:
0.95

Neutral correlation:
0.70

Risk-Off correlation:
0.25

and/or:

Alpha A contributes positively mainly in Risk-On.
Alpha B contributes positively mainly in Risk-Off.

Such a pair must NOT be automatically classified as redundant.

REGIME SOURCE

Use an existing, frozen, point-in-time regime classification.

Do not build a new regime classifier in C2.

The regime assigned to date t must have been knowable using information
available under the existing point-in-time convention.

Do not classify historical dates using future realized returns.

Store:
- regime source/version;
- regime at each date;
- any user-declared mapping of detailed states into broader regimes.

If no valid point-in-time regime series exists for a requested period,
show REGIME_ANALYSIS_UNAVAILABLE.

Do not infer or fabricate labels.

--------------------------------------------------
4. STANDALONE ALPHA STABILITY
--------------------------------------------------

For every selected alpha show rolling:

- net return;
- annualized volatility;
- daily-excess-return Sharpe;
- hit rate;
- turnover / traded notional under the existing convention;
- average risky exposure;
- drawdown from its actual alpha-stream NAV.

Use the existing Sharpe convention:

excess_t = net_return_t - declared_daily_cash_yield_t

Sharpe
=
sqrt(252) * mean(excess_t) / sample_std(excess_t)

Undefined metrics remain undefined.

Do not rank candidates automatically.

Show:
- rolling metric time series;
- median;
- interquartile range;
- minimum/maximum;
- number of valid windows.

--------------------------------------------------
5. REGIME-CONDITIONAL ALPHA PERFORMANCE
--------------------------------------------------

For each alpha and each sufficiently populated regime calculate:

- observation count;
- mean daily excess return;
- annualized volatility;
- conditional Sharpe;
- hit rate;
- average risky exposure;
- average turnover/cost where meaningful.

These are CONDITIONAL statistics.

Do not concatenate non-contiguous regime observations and call the
result a continuous-regime equity curve.

Do not report maximum drawdown on a discontinuous filtered sequence
unless the methodology explicitly uses contiguous regime episodes.

For each regime also show individual CONTIGUOUS EPISODES:

- episode start/end;
- number of observations;
- cumulative alpha return during the episode.

This allows the PM to distinguish persistent regime behavior from
one exceptional episode.

--------------------------------------------------
6. REGIME-CONDITIONAL INCREMENTAL CONTRIBUTION
--------------------------------------------------

Reuse C1 full-versus-exclusion child policies.

Do NOT create a new attribution methodology.

For a selected alpha k:

Full Policy
versus
Policy Without k

Use the already reconciled B3 daily ledgers.

For each regime, calculate both policies' statistics using the SAME
set of regime-labeled dates.

Report:

DeltaMeanReturn_r
=
MeanReturn_full,r - MeanReturn_without_k,r

DeltaVol_r
=
Vol_full,r - Vol_without_k,r

DeltaSharpe_r
=
Sharpe_full,r - Sharpe_without_k,r

DeltaCost_r
=
Cost_full,r - Cost_without_k,r

and matched-date allocation distances.

Do not call these causal effects.

Label:

“Conditional incremental policy comparison.”

Do not reoptimize a separate portfolio using only Risk-On days or only
Risk-Off days.

The original policy remains point-in-time and is simply evaluated
conditionally by the regime that occurred.

This distinction is mandatory.

--------------------------------------------------
7. ROLLING INCREMENTAL CONTRIBUTION
--------------------------------------------------

For user-selected alphas, rerun or reuse C1-style comparisons over
predeclared rolling DEVELOPMENT windows.

The experiment must define before execution:

- rolling window length;
- step size;
- selected alpha IDs;
- maximum number of candidates.

Default:
- window = 252 observations;
- step = 63 observations;
- maximum 5 selected alphas per C2 experiment.

Do not automatically run every possible exclusion across the library.

For each alpha and window report:

- Full vs without-alpha net return delta;
- Sharpe delta;
- volatility delta;
- drawdown delta;
- cost delta;
- alpha-level allocation distance;
- underlying-asset allocation distance.

Show the time series of these deltas.

Also show factual counts such as:

Positive DeltaSharpe windows:
7 / 10

Do NOT convert this into an automatic quality score.

--------------------------------------------------
8. REGIME COMPLEMENTARITY VIEW
--------------------------------------------------

Create a pairwise diagnostic specifically for the user's point:

Two alphas may be highly correlated overall but useful in different
regimes.

For a selected alpha pair show one compact table:

- full-sample return correlation;
- rolling correlation median/range;
- correlation by regime;
- exposure similarity by regime;
- each alpha's conditional Sharpe by regime;
- each alpha's C1 incremental contribution by regime;
- observations per regime.

Add a descriptive evidence flag only when rules are satisfied.

Allowed flags:

PERSISTENTLY_SIMILAR
REGIME_DIVERGENCE_OBSERVED
INSUFFICIENT_REGIME_EVIDENCE

REGIME_DIVERGENCE_OBSERVED may be shown when:

- the full-sample correlation is high according to a transparent,
  user-configured threshold;

AND

- at least one sufficiently populated regime shows materially lower
  correlation OR materially different conditional contribution profiles.

Thresholds must be displayed and versioned.

The flag is descriptive.
It must NOT remove, merge or reweight either alpha.

--------------------------------------------------
9. INSUFFICIENT DATA RULES
--------------------------------------------------

All rolling and regime statistics require explicit minimum observations.

Defaults:

- rolling correlation: minimum 40 paired observations;
- regime correlation: minimum 30 paired observations;
- conditional Sharpe: minimum 30 daily observations;
- rolling C1 contribution window: must contain at least two valid
  portfolio decisions and sufficient B2 estimation history.

If requirements fail:

INSUFFICIENT_HISTORY

Do not:
- fill correlation with zero;
- annualize tiny samples silently;
- collapse missing regimes into another regime;
- shorten windows without telling the user.

--------------------------------------------------
ACCEPTANCE TESTS
--------------------------------------------------

T1 — Rolling stability correctness

Use deterministic alpha returns with independently known rolling
means, volatility and Sharpe.

Verify every valid window within 1e-8.

Confirm insufficient windows remain undefined.

T2 — Regime-conditioned statistics

Construct a deterministic point-in-time regime series.

Independently calculate conditional return, volatility, Sharpe,
hit rate and observation counts.

Match within 1e-8.

Changing future regime labels or prices must not alter earlier outputs.

T3 — HIGH FULL-SAMPLE CORRELATION / REGIME DIVERGENCE

Create two alphas whose total-sample correlation is high, but whose
relationship differs materially across regimes.

Example fixture must produce:

- high full-sample correlation;
- high correlation in one regime;
- materially lower correlation in another regime;
- distinct regime-conditioned performance or incremental contribution.

PASS only if:

- all conditional values are correctly displayed;
- REGIME_DIVERGENCE_OBSERVED can be triggered under its frozen rule;
- neither alpha is removed, merged or reweighted.

This test directly protects the regime-complementarity use case.

T4 — Persistent similarity

Create two economically similar alpha streams.

Verify:

- high full-sample correlation;
- high rolling correlation;
- high sufficiently populated regime correlations;
- high exposure similarity.

PERSISTENTLY_SIMILAR may be displayed.

PASS only if both candidates remain available and no automatic
selection/deletion occurs.

T5 — Conditional incremental contribution

Use an independently run C1 full-versus-exclusion experiment.

Reconcile regime-filtered full and exclusion ledger statistics and
their deltas within 1e-8.

Verify C2 does not reoptimize a special hindsight regime portfolio.

T6 — Rolling incremental contribution

For at least three predeclared rolling development windows, compare
C2 results against independent C1/B3 child runs.

Metrics and allocation distances must match within 1e-8.

No best-window or best-alpha promotion occurs.

T7 — Missing and sparse regime evidence

Create:
- a regime with too few observations;
- missing regime labels;
- a period with sufficient total history but insufficient regime history.

PASS only if affected statistics explicitly report insufficient evidence
rather than zero, interpolation or another regime.

T8 — Real UI/API persistence and replay

Create a C2 experiment through the actual UI.

Include at least:
- two alphas;
- more than one regime;
- rolling diagnostics;
- one incremental-contribution diagnostic.

Change working settings, reload with a fresh client, retrieve and replay.

Require:
- unchanged identities/configuration;
- zero unexpected differing fields;
- maximum numerical replay difference <= 1e-8;
- visible successful replay result.

Run all Stage A, B1, B2, B3 and C1 regression suites plus typecheck.
