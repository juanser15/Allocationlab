B1 — OPTIMIZATION INPUTS & AUDITABLE ALPHA STREAMS

CLOSED-SCOPE IMPLEMENTATION

This replaces the earlier “B1: asset-only Minimum Variance” task.

PRODUCT REQUIREMENT

Allocation Lab must distinguish three optimization objects:

1. Asset returns.
2. Predictive signals / factors.
3. Tradable alpha streams.

These are alternative representations, not three fixed portfolio models.

This task implements their input preparation, economic definitions,
traceability and technical admissibility.

It does NOT implement new allocation solvers, automatic alpha selection,
predictive coefficient fitting, PCA or model ensembles.

SUCCESSFUL USER OUTCOME

The user can select five assets, define multiple transformations on each,
and inspect the resulting signals and explicitly defined alpha streams.

Every stream must expose its historical positions, returns, cash and costs.

Five assets may support thirty candidate alphas.
Thirty candidates must not be presented as thirty independent bets.

1. PRESERVE THE EXISTING BASE
--------------------------------------------------

Reuse A1 execution/accounting, A2 immutable snapshots and Validation Runs,
and A3 implemented factor calculations.

Do not rebuild these systems or introduce a parallel backtester.

Preserve existing saved runs and their original semantics.

Keep the existing allocation workflow operational.

--------------------------------------------------
2. THREE DISTINCT INPUT TYPES
--------------------------------------------------

ASSET RETURNS

Record:
- instrument ID;
- dataset identity;
- dated price/return series;
- price-adjustment convention;
- calendar and return units;
- coverage and missing-data status.

SIGNAL / FACTOR

Record:
- stable definition ID and version;
- parent asset(s) and required peer universe;
- executable calculation type;
- parameters, lookback and lag;
- direction and normalization;
- raw and transformed values;
- observation and availability timestamps;
- data lineage.

A signal value is NOT automatically an expected return or tradable return.

Render the formula from the executable definition.
Treat editable description text as commentary, not executable methodology.
Do not introduce arbitrary formula evaluation in B1.

ALPHA STREAM

An alpha stream requires:
- signal definition(s);
- an explicit signal-to-position rule;
- applicable asset universe;
- reference-capital convention;
- cash treatment;
- position-update schedule;
- execution assumptions;
- historical target and actual positions;
- daily asset P&L, cash P&L, costs and net returns;
- definition, data and engine versions.

A stream without an executable position rule is INCOMPLETE,
not optimization-ready.

Returns without an exposure mapping may be retained as research data,
but must not be presented as deployable asset allocations.

--------------------------------------------------
3. IMPLEMENT TWO EXPLICIT POSITION MAPPINGS
--------------------------------------------------

Use existing executable factors; do not create new factor mathematics.

Provide two reference mappings:

A. SINGLE-ASSET LONG / CASH

At a decision time, for a declared signal u and threshold q:

target asset fraction = g, if u > q;
target asset fraction = 0, otherwise.

Residual reference capital remains in cash.

B. CROSS-SECTIONAL LONG-ONLY

For eligible assets at the decision time:

a_i = max(u_i - q, 0)

If sum(a_i) > 0:

target asset fraction_i = g * a_i / sum(a_i)

Otherwise, reference capital remains in cash.

For both mappings:

- u must explicitly identify raw, oriented or normalized signal units;
- q and g are user-configured and versioned;
- g is between 0 and 1 for THESE long-only mappings;
- direction must not be applied twice;
- missing observations are not equivalent to signals below threshold;
- cross-sectional normalization uses the declared peer universe,
  not a single ticker silently ranked against itself;
- quantities drift between scheduled trades under A1;
- an explicit flat signal is a valid cash position, not missing data.

These mappings are initial supported policies, not universal product limits.

Do not silently infer a trading rule from a factor name.
Do not tune thresholds or mappings against historical performance.
Unsupported position policies must return an explicit unsupported state.

--------------------------------------------------
4. TEMPORAL AND ACCOUNTING CONTRACT
--------------------------------------------------

Generate streams using the existing A1 accounting engine.

Preserve:
- signal information cutoff;
- signal timestamp;
- execution timestamp;
- positions before and after execution;
- daily holdings drift;
- cost and cash accounting;
- missing-held-price protection.

New positions cannot earn returns ending before their execution.

Do not add another lag on top of A1 accidentally.
Do not enable next_open without actual opening-price support.

Historical transformations requiring fitted parameters must use only
observations available at the relevant decision time.

Do not fit scaling, thresholds or eligibility on the complete history
and reuse those fitted values in earlier periods.

Record warmup/unavailable periods explicitly.
Do not pad them with zero returns.

Compute net daily stream returns from its actual NAV changes.
Expose asset P&L, cash P&L and cost components separately.

Adjusted-price simulations must be identified as such; do not claim
broker-level corporate-action accounting that is not implemented.

--------------------------------------------------
5. MAP ALPHA ALLOCATIONS BACK TO ASSETS
--------------------------------------------------

Create a deterministic mapping utility.

At a declared timestamp:

w_assets = H * b

where:
- H contains asset exposures per unit of each alpha's reference capital;
- b contains capital fractions assigned to the alpha streams;
- w_assets contains aggregate asset exposures.

Include each stream's residual cash and any unallocated master cash.
Count cash exactly once.

Distinguish:
- target exposures;
- actual held exposures;
- alpha capital weights;
- resulting asset weights.

Do not use target weights as if they were already executed holdings.

B1 may accept supplied weights b to test and preview this mapping.
Label them USER-SPECIFIED, not optimized.

For this task, support nonnegative capital fractions with sum(b) <= 1.
This is the initial composition capability, not a permanent constraint
on future optimization.

For unsupported signed or leveraged composition, return an explicit
capability error rather than inventing financing assumptions.

Do not calculate aggregate realized net returns by blindly summing
standalone net alpha returns.

The mapping is an exposure identity.
Master-book returns and costs require asset-level execution accounting;
standalone stream costs are not deducted again from a consolidated book.

--------------------------------------------------
6. TECHNICAL ADMISSIBILITY, NOT PERFORMANCE SELECTION
--------------------------------------------------

Mark each input:

- READY
- INCOMPLETE
- INSUFFICIENT_HISTORY
- INVALID_DATA
- UNSUPPORTED

READY means technically usable, not profitable or statistically validated.

Checks must cover:
- supported executable definition;
- sufficient history for its actual lookbacks/lags;
- timestamp consistency;
- required assets/benchmark;
- finite values;
- declared normalization and capital convention;
- valid position mapping for deployable streams.

Do NOT reject a candidate merely because:
- standalone Sharpe is low or negative;
- standalone IC is weak;
- correlation with another candidate is high.

Do not add automatic performance thresholds or select the highest
in-sample Sharpe.

Display reasons for exclusions.
Preserve candidate definitions and historical results.

--------------------------------------------------
7. DEPENDENCE AND EXACT DUPLICATES
--------------------------------------------------

Display three separately labeled quantities:

1. Signal correlation.
2. Alpha-return correlation.
3. Asset-exposure similarity.

Use only observations available through the selected cutoff.

For correlations:
- show date window and paired observation count;
- require an explicit minimum observation count;
- do not replace undefined correlations with zero;
- do not silently pool incompatible signal units or different panels;
- signal correlations must identify their asset/peer scope.

For exposure similarity:
- compare aligned asset-exposure vectors;
- use a documented metric;
- zero-exposure vectors must not generate fake correlation values.

These are descriptive diagnostics, not automatic deletion rules.
Do not implement clustering or PCA in B1.

Identify exact duplicates using a canonical fingerprint of the executable
definition, parameters, input universe, mapping and execution convention.

Names alone must not define distinct economic candidates.
Identical definitions can retain separate display aliases but must not
create additional effective optimization dimensions.

Do not merge candidates merely because their realized returns happen
to match in the observed sample.

Near-duplicates remain distinct and available.

--------------------------------------------------
ACCEPTANCE TESTS
--------------------------------------------------

T1 — Type separation
A raw factor-score series cannot masquerade as an alpha-return series.
An alpha without a position rule is blocked with an explicit reason.

T2 — Five assets, thirty definitions
Using five controlled test assets and six explicitly configured
transformations per asset, prepare thirty distinct candidate definitions.
No cloned placeholder outputs; each retains its own lineage and mapping.

T3 — Known mapping and cash
Using independently calculated small examples, verify both position
mappings, H*b, residual cash and a no-position case.
Numerical agreement within 1e-8.

T4 — Timing and no future contamination
Change observations strictly after a cutoff.
Earlier signal values, targets, executions and stream P&L remain unchanged.
A purchase cannot capture the pre-purchase price jump.

T5 — Accounting and costs
Each generated stream reconciles to the existing A1 ledger within 1e-8.
Cash and costs are counted once.
Holding periods do not introduce implicit daily target rebalancing.

T6 — Admissibility versus performance
Valid weak-performing and highly correlated candidates remain available.
Missing required inputs and invalid held prices produce explicit states,
not invented zeros or a misleading READY status.

T7 — Duplicate identity and configurable mandate
An identical definition under another name does not add an effective
candidate; a genuinely different rule remains distinct even if sample
returns coincide.
A new five-asset preparation does not inherit the June mandate silently.

T8 — Persistence and UI integration
Prepare and save inputs; change working definitions/data; reload.
The saved version retains its original inputs and reproduces its results.
Exercise the real UI/API flow, not only isolated helper functions.

Run existing A1, A2/A2.1 and A3 regression suites.

Synthetic data is allowed only in clearly identified automated tests,
never as market evidence or production results.

--------------------------------------------------

Return a concise B1 completion report with:

- definition of reference capital and cash treatment;
- one worked signal-to-position-to-return example;
- T1–T8 expected/observed results and PASS/FAIL;

Do not mark tests PASS without executing them.
Do not claim predictive validation or a completed alpha optimizer.

One implementation pass, followed by at most one targeted repair pass.
If a required test still fails, stop and report the specific blocker.

If all eight tests and regression suites pass, B1 is CLOSED.
Stop. Do not start the solver or expand the scope.
