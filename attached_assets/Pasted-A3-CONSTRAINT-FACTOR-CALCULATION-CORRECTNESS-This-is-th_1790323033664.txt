This is the FINAL CLOSED-SCOPE task of Stage A.

Do not add portfolio models.

GOAL

1. Ensure final portfolio weights satisfy the constraints the application claims to enforce.
2. Ensure every existing factor calculation matches its displayed name, formula, parameters and settings.
3. Remove or explicitly disable misleading functionality that is not actually implemented.

--------------------------------------------------
PART 1 — PORTFOLIO CONSTRAINT CORRECTNESS
--------------------------------------------------

Separate these concepts explicitly:

A. Minimum factor score for eligibility.
B. Minimum portfolio weight for an included ETF.
C. Maximum ETF weight.
D. Target / required number of active ETFs.

Do not use one parameter for more than one concept.

FINAL-WEIGHT RULE

Constraints must be checked AFTER:

- score weighting;
- prior-weight blending;
- normalization;
- turnover adjustment;
- any other transformation affecting weights.

Do not assume that a cap applied earlier is still valid afterward.

For the current institutional mandate, support and test:

- Cash minimum: 50%
- Cash maximum: 60%
- ETF maximum weight: 10%
- Included ETF minimum weight: 5%
- Required active ETF count: 8

For every final allocation:

cash + sum(ETF weights) = 100%

within numerical tolerance.

For every ETF:

weight = 0
OR
5% <= weight <= 10%

when these mandate settings are active.

If constraints are infeasible, DO NOT silently relax them.

Return an explicit infeasibility result explaining which constraints conflict.

Example:

“Constraint set infeasible: required 8 active ETFs with current eligibility leaves only 6 eligible assets.”

--------------------------------------------------
PART 2 — FACTOR SEMANTIC CORRECTNESS
--------------------------------------------------

Audit every currently supported factor type.

For every factor, ensure these five items agree exactly:

1. Display name
2. Displayed formula
3. Input data
4. Parameter settings
5. Executed calculation

No factor may claim one methodology while executing another.

SPECIFIC CURRENT ISSUES TO FIX

A. TREND QUALITY

The current description implies trend direction and log-price trend quality, while the existing implementation can assign high quality to a strongly falling linear trend because it uses unsigned R².

Implement the declared methodology consistently.

Use log prices over the configured lookback.

Estimate:

log(P_t) = alpha + beta * t + epsilon_t

Trend Quality must preserve direction.

Use:

TrendQuality = sign(beta) * R²

before cross-sectional normalization.

A clean rising trend should be positive.
A clean falling trend should be negative.

Display the exact formula actually used.

B. RESIDUAL MOMENTUM

Do not label simple ETF return minus benchmark return as “Residual Momentum”.

If the current engine does not implement an actual residual-return methodology, mark residual_momentum as UNSUPPORTED / unavailable.

Do not silently alias it to Relative Strength.

Relative Strength may continue to use:

ETF return - benchmark return

with its proper label.

C. CORRELATION STABILITY

Do not calculate Correlation Stability using the identical formula as Diversification Benefit.

If a distinct temporal stability calculation is not already properly implemented, mark correlation_stability as UNSUPPORTED.

Do not pretend it measures stability when it only measures average correlation.

D. WINSORIZATION

If winsorization is configurable and presented as affecting a factor, it must actually be applied before normalization.

Implement the configured winsorization behavior.

If a winsorization option cannot be implemented correctly, disable that option instead of ignoring it.

E. NORMALIZATION

Verify that:

- percentile normalization;
- z-score normalization;
- robust-z normalization;

produce the stated transformation.

Display and use the exact same methodology.

F. DIRECTION

“Higher is better” and “Lower is better” must actually reverse factor preference consistently before normalization/scoring.

G. MISSING VALUES

Missing factor values must follow the explicitly configured missing-data policy.

Do not silently treat missing observations as valid zeros unless ZERO is explicitly the selected policy.

Factors unavailable for a ticker must be identifiable in the calculation output.

Effective factor weights may renormalize across available factors only according to the documented policy.

--------------------------------------------------
AUTOMATED ACCEPTANCE TESTS
--------------------------------------------------

TEST 1 — Final constraint invariants

Generate feasible synthetic scores and prior weights.

After ALL portfolio transformations:

- cash is within configured range;
- active ETF weights satisfy min/max;
- required position count is satisfied;
- total weights equal 100%.

PASS only if final output satisfies every constraint.

TEST 2 — Post-blend cap protection

Construct a case where prior-weight blending would push an ETF above its maximum weight.

PASS only if the FINAL allocation remains within the configured cap.

TEST 3 — Infeasible constraints

Provide only 6 eligible ETFs while requiring 8 active positions.

PASS only if the engine returns explicit infeasibility and does not silently relax the requirement.

TEST 4 — Trend Quality direction

Use two deterministic synthetic series:

A: clean exponentially rising price series.
B: clean exponentially falling price series.

PASS only if:

TrendQuality(A) > 0
TrendQuality(B) < 0

and both reflect high absolute trend quality.

TEST 5 — Unsupported semantic aliases

Verify:

- residual_momentum is not computed as plain Relative Strength;
- correlation_stability is not computed as Diversification Benefit.

PASS if each has a genuinely correct distinct implementation OR is explicitly marked unsupported.

TEST 6 — Winsorization

Create an extreme cross-sectional outlier.

Run the same factor with winsorization OFF and ON.

PASS only if the configured winsorization produces the documented transformed values.

TEST 7 — Direction and normalization

Using known deterministic values, verify:

- higher-is-better ranking;
- lower-is-better ranking;
- percentile;
- z-score;
- robust-z.

PASS only if calculated values match the documented formulas within numerical tolerance.

TEST 8 — Composite reconciliation

For a deterministic set of factor values and weights, independently calculate:

sum(
effective factor weight
× normalized factor score
)

PASS only if it equals the engine composite score within 1e-8.
