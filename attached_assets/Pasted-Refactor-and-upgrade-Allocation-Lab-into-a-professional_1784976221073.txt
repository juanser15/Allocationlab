Refactor and upgrade Allocation Lab into a professional PM-level institutional portfolio optimizer.

The goal is not to simplify away the analytics. The goal is to preserve full quantitative transparency while imposing strict hierarchy, clean navigation, simple commands, and coherent workflow dependencies.

NON-NEGOTIABLE PRODUCT PRINCIPLES

1. Keep the four main modules unchanged:
   - Dashboard
   - Portfolio Lab
   - Research Lab
   - Investment Committee

2. Keep Settings/Data as a global top-right utility drawer, not a main tab.

3. Complexity should exist in the engine and analytical detail, but the interface must remain ordered and navigable.

4. Show real formulas, factor calculations, charts, model diagnostics, backtests, stability tests, robustness metrics, and attribution.

5. Never replace quantitative evidence with generic AI prose.

6. Never show placeholder, fake, uniform, or mocked scores.

7. Use explicit “insufficient data” or blocked states when calculations cannot be performed.

8. Outputs must never appear before the inputs and calculations that generate them.

9. Preserve the current institutional white/navy/gray visual system.

10. Use progressive disclosure:
    - executive summary first;
    - detailed calculations inside internal tabs, drawers, accordions, and drilldowns.

PORTFOLIO LAB — OPTIMIZER PRO

Inside Portfolio Lab, create an Optimizer Pro workspace with these internal tabs in this exact order:

1. Overview
2. Factors
3. Regimes
4. Models
5. Backtest & Out-of-Sample
6. Stability & Robustness
7. Constraints
8. Final Allocation

Use only two main commands:

- Run Optimizer
- Run Validation

Run Optimizer generates the current recommended portfolio.

Run Validation runs the official historical backtest, walk-forward validation, bias audit, and robustness tests.

4. MODELS
--------------------------------------------------

Run exactly three default portfolio construction engines:

A. Momentum / Trend Model

Objective example:

maximize:
score' * w
- lambda_risk * w' Sigma w
- lambda_turnover * ||w - w_previous||_1

B. Minimum Variance Model

Objective:

--------------------------------------------------
5. BACKTEST & OUT-OF-SAMPLE
--------------------------------------------------

Add the official portfolio-process backtester inside Optimizer Pro.

This is not a static backtest using today’s weights.

At every historical rebalance date, the engine must:

1. Use only information available up to that date.
2. Recompute all factors.
3. Estimate the market regime.
4. Apply regime-dependent factor weights.
5. Run all three allocation models.
6. Build the ensemble allocation.
7. Apply constraints.
8. Execute trades at the next available close or next open.
9. Deduct transaction costs and slippage.
10. Include cash yield or cash drag.
11. Move to the next rebalance date.

Prevent:

- look-ahead bias;
- data leakage;
- execution timing errors;
- using final-period parameters in earlier periods;
- applying current weights retrospectively.

Configuration:

- start date;
- end date;
- benchmark;
- monthly / weekly / custom rebalance frequency;
- next-close or next-open execution;
- transaction costs;
- slippage;
- cash yield;
- warm-up period;
- training window;
- rolling or expanding window;
- minimum data history;
- universe treatment.

Results:

- net equity curve;
- gross equity curve;
- benchmark curve;
- excess return;
- CAGR;
- annualized volatility;
- Sharpe;
- Sortino;
- Calmar;
- maximum drawdown;
- turnover;
- hit ratio;
- information ratio;
- monthly returns table;
- rolling Sharpe;
- rolling volatility;
- rolling drawdown;
- rolling beta;
- regime-conditioned performance;
- model-conditioned performance.

Clearly separate:

- In-Sample
- Validation
- True Out-of-Sample

Add walk-forward testing:

Train[t-L : t]
Trade[t+1 : t+h]

Show rolling out-of-sample results.

Add attribution:

- ETF contribution;
- factor contribution;
- model contribution;
- regime contribution;
- cash drag;
- transaction costs;
- slippage;
- implementation shortfall.

Backtest diagnostics must remain hidden until Run Validation has completed.

Before execution show:

“Validation has not been run. Configure assumptions and select Run Validation.”

6. STABILITY & ROBUSTNESS
--------------------------------------------------

Show a complete robustness framework.

Tests:

A. Parameter Perturbation
- factor weights ±10%;
- factor weights ±20%;
- lookback changes;
- turnover penalty changes;
- cash range changes;
- ETF cap changes.

B. Bootstrap / Resampling
- resampled returns;
- resampled covariance;
- portfolio weight dispersion;
- asset-selection frequency.

C. Covariance Sensitivity
- sample;
- EWMA;
- shrinkage.

D. Model Disagreement
- weight distance;
- asset overlap;
- risk disagreement;
- turnover disagreement.

E. Turnover Sensitivity
- different turnover penalties;
- resulting turnover;
- resulting score/risk changes.

F. Rolling Out-of-Sample Stability
- rolling Sharpe;
- rolling drawdown;
- rolling asset selection;
- rolling regime fit.

G. Constraint Sensitivity
- identify which constraints materially change the solution.

Metrics should include formulas.

Example weight stability:

WeightStability =
1 - 0.5 * sum_i |w_i_base - w_i_perturbed|

Example model agreement:

ModelAgreement =
1 - average_k ||w_k - mean(w)||_1

Create a transparent robustness score:

Robustness =
0.25 * ParameterStability
+ 0.20 * BootstrapStability
+ 0.20 * CovarianceStability
+ 0.20 * ModelAgreement
+ 0.15 * OutOfSampleStability

Display:

- total score;
- each component;
- formula;
- test results;
- pass / warning / fail;
- confidence intervals where available.

Do not show only a generic 0–100 number.

Clicking each robustness component should open the underlying calculation and charts.
